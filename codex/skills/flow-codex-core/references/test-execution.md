# 执行已有测试

仅用于已有测试的执行选择；测试设计与环境维护是不同任务。配置、脚本、构件或观测条件不足时，报告具体缺口，不将执行自动扩大成平台开发。

从 config 定位测试仓，先读项目 playbook 和现有 runner 契约。优先采用已经接入项目 runner 的复用命令；脚本存在不等于适用于本次版本。核对本次构件、配置、PID/启动时间和健康，再运行选定场景。缺失服务只用既定启动适配；身份不符的旧进程不自动停止或接管。

已存在且仍适用的 test-design、test-plan、场景契约不重新生成。正式全量执行仍遵循 controller 和现有验证门禁；独立运行只证明所选范围，不补造 controller 状态或全量 PASS。

共同前置失败后不执行用例、不自动修复配置/源码/中间件，也不重复启动整套环境。保存首个失败证据；仅在输入改变或明确重试授权后重试，环境维护须另有明确授权。现有时间预算继续生效。

若项目成功路径尚未接入 runner，明确报告接线缺口，不能绕过版本、配置和进程身份核对，也不在普通业务测试中改写通用 runner。
