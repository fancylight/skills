# 开发文档增量更新规则

> **受众**：业务项目中执行 `flow-codex-report` / `/flow:report` 的 Agent。
> skills 仓库维护者改本文件后须同步 report skill，并跑 `codex/validate.ps1`（见仓库根 MAINTENANCE.md §3.3）。

---

## 数据源

从以下来源提取**人读摘要**（禁止复制 OpenSpec 中的文件路径表）：

1. 本 spec 的 OpenSpec `design.md`（实现方案、DDL 语义、接口列表）
2. 本 spec 的 git commit 与变更文件类型
3. 已同步的 Apifox 结果

---

## 按章节更新

| 章节 | 触发条件 | 动作 |
|------|----------|------|
| **§3.2.4 接口设计** | 本 spec 新增或修改 HTTP/Feign 接口 | 补全或更新表格行；执行 Apifox MCP 同步（见 report skill）；将「待录入」替换为实际链接 |
| **§3.2.2 存储与数据** | 本 spec 有 DDL 或持久化语义变化 | 追加/更新表与字段**语义**、兼容策略；**不写**完整 SQL（SQL 在 `发版记录.md`） |
| **§3.2.3 数据流转** | 新增跨服务调用、持久化链路或运行时消费路径 | 更新 `text` 流转图（服务名 + 接口路径级） |
| **§3.2.1 业务规则** | 实现与 design 骨架有收敛或澄清 | 仅更新有变化的规则表述；不引入 spec/类名 |
| **§4.2 SQL、配置** | 本 spec 有 DDL 或部署配置变更 | 增加摘要行（类型 + 简述 + 「详见发版记录」） |
| **§3.1 前端** | 本 spec 改前端且为模块级可见变化 | 更新模块/页面表；**禁止**文件清单 |

## Apifox 同步（§3.2.4）

读取 `开发文档.md` **§3.2.4** 接口表格：

| 表格状态 | 操作 |
|---------|------|
| 已有 Apifox 链接 + ✏️修改 | MCP 更新接口定义 |
| 待录入 + 🆕新增 | MCP 创建接口 |
| 待录入 + ✏️修改 | 提示先手动创建 |
| 无法匹配 | 汇报中逐条列出，禁止静默跳过 |

POST requestBody 须用 jsonSchema 模式（`type: application/json` + `parameters: []` + 字段在 `jsonSchema.properties`）。
