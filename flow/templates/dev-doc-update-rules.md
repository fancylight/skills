> skills 仓库维护者改本文件后须同步 report skill，并跑 `codex/validate.ps1`（见仓库根 MAINTENANCE.md §3.3）。
>
> 全文写作尺度见同目录 `dev-doc-maintenance.md`（尤其 §4.1 / §4.2 / §4.3 与禁止项）。

## 按章节更新

| 章节 | 触发条件 | 动作 |
|------|----------|------|
| **§3.2.4 接口设计** | 本 spec 新增或修改 HTTP/Feign 接口 | 补全或更新表格行（「服务」列填**可部署服务名**）；执行 Apifox MCP 同步；将「待录入」替换为实际链接 |
| **§3.2.2 存储与数据** | 本 spec 有 DDL 或持久化语义变化 | 追加/更新表与字段**语义**、兼容策略；完整 SQL 写入 **§4.2**，此处不写「见发版记录」 |
| **§3.2.3 数据流转** | 新增跨服务调用、持久化链路或运行时消费路径 | 更新 `text` 流转图（**服务名 + 接口路径级**；禁止类名流水） |
| **§3.2.1 业务规则** | 实现与 design 骨架有收敛或澄清 | 仅更新有变化的规则表述；不引入 spec/类名 |
| **§4.1 服务-分支** | 本 spec 涉及可部署单元未列出或误写为仓库名 | 按可部署/运行单元补行或拆行；`git 仓库` 列可重复；禁止一行只写仓名冒充服务 |
| **§4.2 SQL、配置** | 本 spec 有 DDL 或部署配置变更 | **直接写入** DDL/SQL（代码块）或配置内容；无则写「无」。禁止「详见发版记录.md / openspec / 本地路径」 |
| **§4.3 测试与验收** | 实现澄清了验收边界，或 design 骨架需收敛 | 只写**业务验收语义**（验收点 + 期望行为）。禁止测试类名、本机地址、启动清单、commit hash、spec id |
| **§3.1 前端** | 本 spec 改前端且为模块级可见变化 | 更新模块/页面表；**禁止**文件清单 |

## §4.1 / §4.2 / §4.3 回写要点（必读）

### §4.1 服务-分支

- 服务名称 = **可部署/运行单元**，不是 git 仓库名。
- 多模块仓（如 `glm-attendance`）须拆成实际服务行（如 `clock-record-generate`、`attendance-decide`、`labor-time-calculate`）；仓库列可重复。
- 禁止：`服务名称` 填 `glm-attendance` 这类仓名。

### §4.2 SQL、配置

- SQL **写在本节**，开发文档自包含。
- 可与 `发版记录.md` 语义一致，但**不要**用「详见发版记录」代替正文。
- 无配置时写「无」。

### §4.3 测试与验收

- **正例**：按天区分进出日级最多 1 次迟到/早退；不区分进出且首末时间相同只判迟到；跨夜锚点规则；按区间兼容；配置读写回显。
- **反例**：`RuleDailyTest`、`127.0.0.1:9200`、启动服务清单、`commit abc123`、`c2-xxx`。

## Apifox 同步（§3.2.4）

读取 `开发文档.md` **§3.2.4** 接口表格：

| 表格状态 | 操作 |
|---------|------|
| 已有 Apifox 链接 + ✏️修改 | MCP 更新接口定义 |
| 待录入 + 🆕新增 | MCP 创建接口 |
| 待录入 + ✏️修改 | 提示先手动创建 |
| 无法匹配 | 汇报中逐条列出，禁止静默跳过 |

POST requestBody 须用 jsonSchema 模式（`type: application/json` + `parameters: []` + 字段在 `jsonSchema.properties`）。

## 禁止

- 写入 spec 名、`c{n}-`、Flow 内部术语、commit hash
- 粘贴完整 JSON 到 §3.2.4
- 从 `概要设计.md` 整段复制
- 以「详见发版记录.md / openspec / 本地路径」代替 §4.2 正文
- 把 §4.3 写成测试类名、本机地址或本地启动说明
- 把 §4.1「服务名称」写成 git 仓库名
- 类名/方法名堆砌、本地相对路径作为正文依赖
